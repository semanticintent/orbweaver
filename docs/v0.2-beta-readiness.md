# v0.2 beta readiness

This document records the release boundary between Orbweaver's v0.2 alpha
exploration and its beta adoption period. It is a release decision, not a new
runtime contract.

## Recommendation

After the v0.2 alpha-line review passes, publish `0.2.0-beta.1`. The package
is ready for early adopters who need a semantic-first visualization library
with a stable core contract and explicit prerelease expectations.

## What is ready for beta adoption

- Coordinate-free `Graph` input, validation, normalization, layout, and SVG
  rendering.
- Inspection, keyboard and pointer interaction, viewport control, semantic
  annotations, lenses, detail levels, focused paths, legends, and comparison.
- Versioned SVG, PNG, and portable HTML export contracts.
- Proposal validation and review primitives, with no model provider dependency
  in `@semanticintent/orbweaver`.

## What remains experimental or host-owned

- The public website's proposal lab and WebMCP playground are experimental
  host experiences; they are not package APIs and retain human-only acceptance
  and export controls.
- Model-backed proposal generation is optional website work. It must remain
  provider-specific, opt-in, and outside the package.
- Domain adapters, including Mere, RECALL, and CAL, are future consumers. They
  must not become dependencies of Orbweaver core.

## Compatibility promise through beta

The v0.2 beta line treats the public Graph, proposal-validation, rendering,
interaction, viewport, export, and semantic-intelligence APIs as stable for
normal use. A breaking change before `1.0` is allowed only to correct a
material defect, ambiguity, security issue, or demonstrated integration
failure. Each such change requires a migration note and compatibility fixture
where practical.

Experimental website experiences may evolve independently, but their semantic
data must continue to pass the public validation boundary.

500 KiB. It is not a package release blocker: the package's published browser
bundle remains within its documented gate. Treat website code-splitting as a
separate optimization item if a measured user-facing concern emerges.

## Remaining release actions

1. Review the generated light and dark showcase artifacts in a browser,
   including selection, inspector, viewport, and download behavior.
2. Publish concise `0.2.0-beta.1` release notes from this document.
3. Bump the package version, run the release gate from a clean install, then
   publish under the `next` tag before considering `latest`.

## Non-goals for the beta cut

- A freeform diagram editor or authored coordinates.
- AI credentials, SDKs, or provider logic in the package.
- A hosted collaboration service or enterprise architecture repository.
- Automatic acceptance, export, or publication of generated proposals.
